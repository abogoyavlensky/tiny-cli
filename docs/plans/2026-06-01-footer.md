# Optional Root-Help Footer Implementation Plan

> **For agentic workers:** Use executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add an optional `:footer` string to the app spec that renders as trailing text after all sections in `root-help`, like Docker's `Run 'docker COMMAND --help' for more information on a command.` line.

**Tech Stack:** Clojure `.cljc` (cross-target: let-go, Clojure, Babashka), tested via `lgx test-all`.

---

## Design

### Summary

`tiny-cli` generates help text from a plain-data app spec. `root-help`
(`src/tiny_cli/core.cljc:442`) assembles its output by `concat`-ing per-section
line sequences into `join-lines`, which joins with `\n` and filters `nil`
entries. Each trailing block already has a small private helper
(`root-option-built-ins`, `root-command-built-ins`).

This change adds one optional app-spec field, `:footer` (a single string), and
renders it as the final block of `root-help`, preceded by a blank separator
line. `command-help` is intentionally untouched: the footer is root-only,
matching the "after all commands and options" intent.

### Data model

One new optional field on the app spec:

```clojure
{:name "deploy"
 :doc "Deploy one service."
 :footer "Run 'deploy <command> --help' for more info."
 :commands [...]}
```

- `:footer` is a single string. No vector form, no per-command/option footer.
- Authors embed `\n` themselves for multi-line text; the library does not
  post-process the string.
- Consistent with `:doc`, which is also a plain string.

### Rendering

Add one private helper next to the existing section helpers in `core.cljc`:

```clojure
(defn- footer-lines
  [app]
  (when (seq (:footer app))
    ["" (:footer app)]))
```

Append it as the final block in `root-help`'s `concat`:

```clojure
            (root-command-built-ins app)
            (footer-lines app))))
```

`join-lines` already filters `nil`, so a `nil` return contributes nothing.
The blank separator (`""`) lives *inside* `footer-lines`, so the separator only
exists when the footer does — no orphan blank lines.

### Edge cases / data flow

| `:footer` value | `(seq …)` | Rendered |
|---|---|---|
| absent (`nil`) | falsey | nothing, no trailing blank |
| `""` | falsey | nothing, no trailing blank |
| non-blank string | truthy | blank line, then footer text, as the last output |

This reuses the same "no dangling separator" discipline the existing
`optional-docs-render-cleanly` test guards.

### Error handling

None added. `:footer` is not validated, consistent with `:doc` (also
unvalidated). `app-spec-error` is unchanged. A non-string truthy value is not
guarded — same posture as `:doc` today (YAGNI).

### Scope guard

`command-help` (`src/tiny_cli/core.cljc:459`) is not modified, so the footer
never appears in per-command help. A test asserts this explicitly.

## File Structure

- `src/tiny_cli/core.cljc` — add private `footer-lines` helper; append it to
  `root-help`. No other functions change.
- `test/tiny_cli/core_test.cljc` — add footer rendering/scope/absence tests.
- `README.md` — document `:footer` in the app-fields table and show it in the
  root-help example output.

## Tasks

### Task 1: Render `:footer` in root help

**Files:**
- Modify: `src/tiny_cli/core.cljc`
- Test: `test/tiny_cli/core_test.cljc`

- [ ] **Step 1: Write the failing tests**
  In `core_test.cljc`, add a `deftest` (e.g. `footer-rendering`) covering:
  - Given an app with `:footer "Run 'wtr <command> --help' for more info."`,
    `(cli/root-help app)` contains the footer text **and** the footer is
    preceded by a blank line (e.g. assert the substring `"\n\nRun 'wtr"` or
    match `#"\n\nRun 'wtr"`).
  - Same app: the footer is the **last** content in `root-help` — assert it
    ends with the footer (e.g. match `#"for more info\.\z"`), so the test
    guards ordering, not just presence.
  - Same app: `(cli/command-help app "create")` does **not** contain the footer
    text (`(is (nil? (re-find #"--help' for more info" text)))`) — scope guard.
  - App **without** `:footer`: `(cli/root-help app)` does not end with a
    trailing blank line and contains no footer text. Reuse the existing
    `no-doc-app` style; assert output does not match `#"\n\n\z"`.
  - App with `:footer ""`: `(cli/root-help app)` renders identically to the
    no-footer case (no trailing blank, no footer text).
  Define a local `footer-app` in the test (derive from the existing `app`) so
  the shared `app` fixture stays footer-free for the other suites.

- [ ] **Step 2: Run tests to verify they fail**
  Run: `lgx test-all`

  `(seq (:footer app))`, else `nil`) and append `(footer-lines app)` as the
  final block of the `concat` in `root-help`.

- [ ] **Step 4: Run tests to verify they pass**

## Notes

- DRY: one helper, one call site. No changes to parsing, validation, or
  `command-help`.
- YAGNI: no footer validation, no vector form, no per-command footer.
- Backwards compatible: `:footer` is optional; existing specs render unchanged.
